# RAG(检索增强生成)基础概念

## 什么是 RAG

RAG(Retrieval-Augmented Generation,检索增强生成)是一种把"外部知识检索"和"大语言模型生成"结合起来的技术。核心思路:用户提问时,先从知识库中检索出相关片段,把这些片段塞进提示词,再让大模型基于这些资料回答。

## 为什么需要 RAG

1. 大模型的训练数据有截止日期,不知道最新的私有信息(公司文档、产品手册等)。
2. 大模型会"幻觉"——一本正经地编造答案。RAG 让回答有据可查,可以标注引用来源。
3. 相比微调(fine-tuning),RAG 成本低得多:更新知识只需要重新入库文档,不用重新训练模型。

## RAG 的标准流程

离线阶段(入库):
1. 加载(Load):读取 PDF、Markdown、Word 等文档。
2. 切分(Split):把长文档切成大小适中的片段(chunk),片段之间保留少量重叠(overlap),避免语义被切断。
3. 向量化(Embed):用向量模型把每个 chunk 转成一个高维向量(如 2048 维的浮点数数组),语义相近的文本向量距离更近。
4. 存储(Index):向量连同原文、元数据一起存进向量数据库(如 Chroma、Milvus、FAISS)。

在线阶段(问答):
1. 用户提问,问题同样被向量化。
2. 在向量库中做相似度检索,取出最相关的 K 个 chunk。
3. 把 chunk 作为参考资料连同问题一起填入提示词模板。
4. 大模型生成回答,理想情况下会基于资料并注明来源。

## 关键参数

- chunk_size:每个片段的最大长度(按字符或 token 计)。太大则检索不精准,太小则上下文不完整。
- chunk_overlap:相邻片段的重叠长度,通常取 chunk_size 的 10%~20%。
- top_k:每次检索返回的片段数。太少可能漏掉答案,太多会稀释上下文并增加 token 成本。

## 常见优化手段

- 混合检索:同时用向量检索和关键词检索(BM25),取长补短。
- 重排序(Rerank):先粗检索 top 20,再用 rerank 模型精选 top 3~5。
- 问题改写(Condense Question):多轮对话时把历史和当前问题合并改写,避免"它是什么意思?"这类代词导致检索失败。
- 语义切分:按句子/段落语义边界切分,而不是固定字符数。
